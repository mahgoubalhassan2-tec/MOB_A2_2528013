User Flow & Information Architecture

1. Information Architecture (IA) Hierarchy

The application utilizes a persistent 5-section Bottom Tab Bar combined with a nested Native Stack Navigator for deep-dive technical project breakdowns.

[App Launch (Restore AsyncStorage Session Cache)]
│
├── Tab 1: Home Screen (Mandatory Statement, Avatar, Verified Code, Bio, Quick Links)
├── Tab 2: Projects Stack
│ ├── ProjectsListScreen (Browse Filtered Student Projects, Tech Badges)
│ └── ProjectDetailScreen (Nested Stack: Problem, Contribution, Tech, Offline Metrics)
├── Tab 3: Skills & Education (6 Competency Badges, Category Filter, INES Timeline)
├── Tab 4: Profile Editor (Controlled Inputs, 3 Validation Rules, Media Picker, AsyncStorage Save/Reset)
└── Tab 5: About & Release (Academic Metadata, MOB-A2-8013 Hero Card, Privacy/Data-Use Policy)

2. User Flow & State Lifecycle

Workflow Step User Action System / State Transition
1. Cold Start User taps installed app icon on Android launcher. Loads stored JSON payload from @mahgoub_portfolio_profile_v1 via AsyncStorage. Renders Home Screen in <100ms.
2. Project Deep Dive Taps "INES Attendance Tracker" card in Projects tab. Pushes ProjectDetail onto stack with projectId params. Hardware Android Back button pops cleanly back to list.
3. Media Selection Taps "Gallery Selection" or "Camera Capture" in Editor. Requests OS runtime permission. If denied/cancelled, displays non-blocking alert. On selection, caches local URI in component state.
4. Validation & Persistence Inputs custom bio & headline, then taps "Save Profile Changes". Executes 3 validation checks. If valid, serializes state to AsyncStorage and updates global state. If invalid, blocks save and renders inline red error alert.
5. App Restart Test User terminates app process from Android Recents and reopens. AsyncStorage re-populates state automatically. Custom photo, headline, and bio remain 100% intact.

2. Typography Hierarchy & Scalable Text Behavior

Role Size & Weight Large-Text (130% System Font) Behavior
Display H1 24sp / Bold (800) Flexbox container wraps gracefully without truncation or clipping.
Section H2 20sp / Bold (700) Maintains visual priority; adequate vertical margin prevents line collisions.
Body Text 14sp / Regular (400) Line height scales dynamically to 22sp, preventing overlapping lines.
Captions / Chips 12sp / Medium (600) Pill badges wrap across multiple lines using flexWrap: 'wrap'.

3. Accessible Touch Targets & Screen Reader Support

  • Minimum Touch Targets: All buttons and interactive tabs provide a minimum touch dimension of 48 x 48 dp to adhere to Google Android Material Accessibility guidelines.
  • Accessibility Roles & Labels: Every interactive element (e.g., Tab items, Project Cards, Gallery buttons) specifies explicit accessibilityRole="button" and descriptive accessibilityLabel strings for Android TalkBack.
  • Controlled Visual Feedback: Buttons provide immediate tactile feedback via activeOpacity={0.75} and render an active ActivityIndicator during asynchronous AsyncStorage operations.
  • Zero Network Fragility: Core portfolio assets and layouts require no remote CDNs or live web fonts, guaranteeing full structural fidelity in Airplane Mode.
